# 帧鉴 · Cinegraph

[![repo](https://img.shields.io/badge/GitHub-wzyzl%2Fcinegraph-181717?logo=github)](https://github.com/wzyzl/cinegraph)
[![license](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

本地视频拉片工作台。一条命令起来，浏览器里看画面、拖时间线、打注解、出拉片表。

**零第三方依赖**（只要 ffmpeg/ffprobe），所有数据留在本机。

---

## 为什么自己做

先把市面上的摸了一遍，结论如下：

| 工具 | 形态 | 缺什么 |
|---|---|---|
| [CutGo](https://microsoftedge.microsoft.com/addons/detail/giehmlcoajbedmonpcfnjhoiccmmgemi) | Edge/Chrome 插件 | 只在浏览器里，出不了结构化镜头表 |
| [小镜拉片](https://xjstoryboard.com/help/how-to-use-our-extension) | Chrome 插件（SaaS） | 数据在别人服务器 |
| [lapian-notes](https://github.com/bkingfilm/lapian-notes) ★770 | 本地 Web（TS/React） | 重叙事结构，轻视听参数；1 秒/张抽帧，靠 AI 看图 |
| [dsh-film-analysis](https://github.com/Raven-Jackdaw/dsh-film-analysis) | DSH 插件 | 8 维分析很强，但没有连续时间线可视化 |
| [cine-sleuth](https://github.com/LycheeAILab/cine-sleuth) | Agent 插件 | 依赖其云 API 与账号 |
| [video-annotator](https://github.com/ks233/video-annotator) | 纯前端 | 时间线手感最好，但没有自动分镜、没有量化曲线 |

**没有一个同时给你：自动分镜 + 帧级时间线 + 量化曲线（节奏/色温/响度）+ 结构化镜头表。** 所以做了这个。

## 启动

双击 `run.bat`。浏览器会自动打开 `http://127.0.0.1:7788`。

## 导入影片

**点击「打开影片」（或空状态里的「点击选择文件」，或 `Ctrl+O`）→ 浏览器原生的文件选择框。** 选中后流式上传到本地服务（走 `127.0.0.1`，实测 92 MB/s，145 MB 的片子 1.6 秒），落盘到 `data/uploads/`，然后自动分析。

为什么用 `<input type="file">` 而不是后端弹 Windows 原生对话框（`GetOpenFileNameW`）：

| | 浏览器 file input | 后端 Win32 对话框 |
|---|---|---|
| 任务栏 | 挂在浏览器图标下，干净 | **server 进程没有主窗口，Windows 会给这个对话框单独挂一个任务栏按钮** |
| 拿到的东西 | `File` 对象 → 上传 | 真实路径 → 零复制 |
| 145 MB 耗时 | 1.6 秒 | 0 秒 |
| 磁盘占用 | 多一份副本 | 不占 |

复制一份换掉任务栏那个多余图标，值。

另外三条路：

- **拖进窗口** —— 视频拖到页面任意位置，松手即传，和点选走同一条上传管线。
- **最近打开** —— 空状态下列出最近 6 个项目，点一下回到上次进度，注解都在。
- **改用路径浏览** —— 空状态底部的小链接，走路径列表。**这条路不上传、零复制、直接读原文件**，几个 GB 的大片或不想占地方时用它。

上传去重：同名且同大小的文件不会重复落盘，直接复用已有副本。

`data/uploads/` 里的副本可以随时手动删，不影响原文件。支持：mp4 / m4v / mov / mkv / avi / webm / wmv / flv / ts / mpg / mpeg

首次打开一部影片会自动分析（686 秒的片子约 **20 秒**）：

| 步骤 | 做什么 | 说明 |
|---|---|---|
| 读取元信息 | 时长/帧率/画幅/编码 | ffprobe，瞬间 |
| **一次解码，三路输出** | 镜头切点 + 缩略图条 + 亮度色温 | `filter_complex split=3`，全片只解一遍 |
| 音频包络 | 每 50ms 一个峰值 | 只解音频，约 0.7 秒 |

**性能说明**：早期版本把「场景检测 / 抽帧 / 色彩统计」分成三次 ffmpeg 调用，每次都要全片解码一遍（1680×720 H.264 约 22 秒/次），串行下来 60 秒以上。现在合并成一条命令，`split` 后三路并行处理，**18 秒**搞定。

进度条早期会卡在 40% 不动——因为 `tile` 滤镜要攒满 400 帧才吐第一张缩略图，ffmpeg 的 `out_time` 在那之前一直是 0。现在用「真实进度 vs 时间估算取大值」+ 后台心跳驱动，进度从头到尾连续推进。

实测（《回溯》11 分 26 秒 / 20590 帧 / 1680×720）：

```
0.5s  5%   → 9.8s 45% → 10.3s 61%（第一张缩略图吐出，真实进度接管）
        → 17.5s 95% → 18s 解析切点 → 19.6s 完成
```

### 时间线怎么读

四条带子叠在一起就是**后期导演看片的方式**：

- **缩略图带**：全片视图下是压缩后的"胶片色带"，看不出细节是正常的——它在告诉你影调怎么走。**放大后自动变成清晰的逐帧缩略图。**
- **色温带**：把 U/V 按全片范围归一化。青色 = 冷调，暖黄 = 暖调。段落之间的冷暖切换一眼可见。
- **亮度带**：Y 均值。暗部段落（黑场、夜景）会塌下去。
- **波形**：不是为了听声音，是为了看**结构和留白**。哪里音乐顶满、哪里抽空，一目了然。

**三条曲线和你剪的镜头密度是做对照用的。** 声音最响的地方画面切得最快还是最慢？最暗的地方有没有让位给安静？这是《回溯》拉片里最核心的发现，现在你可以自己验证任何一条片子。

## 标注

点时间线上的镜头块，或点右侧列表。

| 字段 | 说明 |
|---|---|
| 入点 / 时长 | 可直接改时间码（`HH:MM:SS.ff`），也能按 `S` 在播放头处切开 |
| 景别 | 大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写 |
| 运动 | 固定 / 推 / 拉 / 摇 / 移 / 跟 / 升降 / 手持 / 斯坦尼康 / 航拍 |
| 光线 | 顺光 / 侧光 / 逆光 / 顶光 / 底光 / 硬光 / 柔光 / 高调 / 低调 / 混合光 |
| 色彩 | 冷调 / 暖调 / 中性 / 高饱和 / 低饱和 / 单色 / 对比色 |
| 功能 | 建立 / 铺垫 / 激励事件 / 递进 / 转折 / 高潮 / 释放 / 过渡 / 收束 |
| 画面 | 谁 在 哪里 做什么 |
| 声音 | 台词 / 音乐 / 音效 / 静默 |
| 备注 | 判断、联想、可复用手法 |

字段可换——改 `server.py` 里 `/api/open` 建项目时写入的 `tags` 即可，或直接改 `data/projects/<id>.json`。

自动保存（改完 900ms 落盘）。

### 改键

点顶栏「⌨ 快捷键」或按 `?`，在面板里点对应项的「改」，然后**直接按下想用的键**。冲突的键会自动从原动作上解绑。设置存在 `localStorage`，刷新不丢；「恢复默认」一键还原。

`Shift` 不单独占位——它会体现在实际字符上（比如 `Shift+,` 得到的键名是 `<`）。`Ctrl` / `Alt` 会作为前缀保留，所以 `Ctrl+S` 和 `S` 是两个不同的槽位。

## 时间线缩放

三种方式，都指向同一个视图状态：

- **滑轨**（时间线右上角）——拖 `－ ——— ＋` 之间的滑块连续缩放，右侧实时显示当前可视时长（`60s` / `全片`）。滚轮缩放时滑块也会跟着动。
- **滚轮** —— 在时间线上滚动，以鼠标位置为锚缩放。
- **`=` / `-` 键** —— 以视窗中心为锚，按 1.6 倍步进。

缩放下限 0.5 秒（约 15 帧），上限全片。缩放时视窗中心保持不动。

## 界面布局可调

两条分隔条，都支持拖动，位置记在 `localStorage['cinegraph.layout.v1']`：

- **时间线上方那条横线** —— 上下拖，调整时间线高度（110px ~ 窗口高-240px）。默认 268px。
- **视频区和侧栏之间那条竖线** —— 左右拖，调整侧栏宽度（260px ~ 窗口宽-460px）。默认 392px。

**双击任一分隔条复位**。拖动时状态栏会实时显示当前像素值。

也可以用 URL 参数临时指定，不改动已保存的布局：

```
http://127.0.0.1:7788/?open=<id>&tl=430&side=470
```

### 时间线拉高之后

各层会按比例重新分配：色温带、亮度带、镜头轨道都跟着长。缩略图带有特殊处理——**单行 filmstrip 的高度和格子宽度没法同时满足画面比例**，硬拉会让人物变形。所以当单行格子太窄而高度又很大时，自动切成 **2~4 行**，每行铺满宽度、显示不同时间段，画面保持原比例不变形。

镜头轨道超过 40px 时也会补一行镜号和时长。


```
http://127.0.0.1:7788/?open=<项目id>            直接打开某个项目
http://127.0.0.1:7788/?open=<id>&t=430&z=26     定位到 430 秒，时间线显示 26 秒窗口
http://127.0.0.1:7788/?open=<id>&keys=1         顺带打开快捷键面板
http://127.0.0.1:7788/?open=<id>&tl=430&side=470  临时指定时间线高度 / 侧栏宽度
```

`t` = 定位时间（秒），`z` = 可见时长（秒）。适合做完一段发给自己或同事。

## 刷新不丢

打开项目时会做两件事：

1. `history.replaceState` 把 `?open=<id>` 写进地址栏 —— **刷新页面自然回到同一个项目**，地址也能直接收藏或发给别人。
2. `localStorage['cinegraph.last']` 记一份 —— 即使地址栏被清空（比如直接访问 `127.0.0.1:7788`），也会自动回到上次的项目。

另外 `localStorage['cinegraph.pos']` 记播放位置（2 秒节流），刷新后从上次停的地方接着看。

## 技术

```
server.py          零依赖 HTTP 服务 + ffmpeg 分析管线（Range 流式播放）
web/index.html     三栏骨架
web/style.css      深色主题
web/timeline.js    Canvas 时间线（缩略图/色带/亮度/波形/镜头/段落 六层）
web/app.js         播放控制、注解 CRUD、导出
data/cache/<id>/   分析产物（meta / cuts / strip / wave / metrics / shots）
data/projects/     项目 JSON（镜头表 + 注解）
```

**分析管线全部走 ffmpeg 滤镜**，没有 Python 图像库依赖：

- 分镜：`select='gt(scene,0.28)'` + `metadata=print`
- 雪碧图：`fps=1,scale=160:-2,tile=20x20:padding=2`
- 波形：`-ac 1 -ar 8000 -f s16le` 直读 PCM
- 亮度/色温：`signalstats` + `metadata=print`

检测灵敏度可以在顶栏拖（0.10–0.60），改完按「重新分镜」。数值越小切得越碎；水下、夜景这种帧间差异小的段落需要调低。

## 已知限制

- 只处理本地文件，不做链接解析（抖音/B站要另外抓，抓到本地文件再拖进来）
- 缩略图每秒 1 帧。要更密（比如每秒 2 帧）改 `server.py` 的 `build_strip(fps=2.0)`，分析时间翻倍
- 不自动做 OCR 字幕识别，台词要手打或从外面导
- 段落轨道（紫块）已支持数据结构，界面还没做编辑入口
